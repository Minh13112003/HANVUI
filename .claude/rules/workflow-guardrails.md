# Quy tắc làm việc — HanVui

## 1. Bàn trước, code sau
- **Không viết code** cho đến khi user nói rõ "bắt đầu code".
- Ý tưởng mới: cùng bàn tính khả thi → nếu hai bên đồng ý thì ghi vào `rule.md` đúng mục, gắn nhãn **[CHỐT]**.
- Chưa đồng ý hoặc còn băn khoăn → ghi vào mục "Câu hỏi mở" (nhãn **[CẦN CHỐT]**), không code.
- Hoãn → nhãn **[SAU NÀY]**.

## 2. Khi cập nhật rule.md
- Giữ ngắn gọn, dùng bullet và heading ngắn.
- Mỗi thay đổi ghi thêm một dòng vào Changelog cuối file (ngày + nội dung).
- Nếu ý mới mâu thuẫn với phần đã chốt: nêu rõ mâu thuẫn và hỏi user trước khi sửa.
- Khi thấy ý tưởng có rủi ro (cân bằng điểm, nội dung quá nhiều, người mới bị bỡ ngỡ), nói thẳng và đề xuất cách xử lý.

## 3. File
- **Không xóa file** nếu user chưa ra lệnh rõ ràng. Thấy file không còn dùng thì hỏi trước.
- Thông tin nghiệp vụ và luật chơi nằm trong `rule.md`. Quy tắc làm việc nằm ở file này.

## 4. Ngôn ngữ
- Trao đổi bằng tiếng Việt, ngắn gọn.
- Nội dung học: tiếng Trung kèm pinyin và bản dịch tiếng Việt.
